# [source: 1] ANSI/SPARC

### 一、 核心概念

ANSI/SPARC 是一種三層式資料庫架構，核心目的在於將「使用者應用程式」與「實體資料儲存」完全分離，藉此達成「資料獨立性」（Data Independence）。

### 二、 三層架構解析

由上（使用者端）至下（實體儲存端）劃分為三層：

1. **外部層 (External Level / View Level)**，又稱「視界層」。
* 最接近使用者。僅呈現特定使用者所需要的局部資料，隱藏其餘無權或不須知道的部分，以簡化操作並提升安全性。


2. **概念層 (Conceptual Level / Logical Level)**，又稱「邏輯層」。
* 描述整個資料庫的邏輯全貌（包含資料實體、關聯性與限制條件）。它整合了所有外部需求，隱藏底層儲存細節，通常由資料庫管理員 (DBA) 負責設計。


3. **內部層 (Internal Level / Physical Level)**，又稱「實體層」。
* 最接近硬體。描述資料在磁碟上的實際儲存方式，包含檔案結構、資料壓縮、存取路徑與索引技術，以追求系統效能最佳化。



### 三、 兩層對應 (Mapping) 與資料獨立性

系統透過層與層之間的「對應機制」來達成資料獨立性：

1. **外部/概念對應 (External/Conceptual Mapping)**
* 欲達成目標為「邏輯資料獨立性」。
* 當「概念層」的邏輯結構發生變更（如新增資料表或欄位）時，只需修改此對應關係，使用者的「外部層」與應用程式皆無須修改。


2. **概念/內部對應 (Conceptual/Internal Mapping)**
* 欲達成目標為「實體資料獨立性」。
* 當「內部層」的實體儲存結構變更（如更換儲存設備、更改索引方式）時，只需修改此對應關係，「概念層」與「外部層」皆無須修改。此種獨立性較易達成。

# 資料庫優缺點及種類：

### 一.

資料庫問世前，資料分散儲存於各應用程式的獨立檔案中，造成資料重複與不一致；資料庫系統將資料集中管理，以解決上述問題。

### 二. 優缺點

* **優點**
1. **降低資料重複（Reduce Redundancy）**：資料集中存放，避免同一資訊重複儲存。
2. **維持資料一致性（Consistency）**：減少重複，即降低前後不一致的風險。
3. **資料共享（Data Sharing）**：多使用者、多應用程式可同時存取同一份資料。
4. **維護資料完整性（Integrity）**：以完整性限制（如鍵、CHECK）確保資料正確。
5. **強化安全性（Security）**：以權限控管限制不同使用者的存取範圍。
6. **提供資料獨立性（Data Independence）**：分為邏輯與實體獨立性（見講義 01）。
7. **備份與復原（Backup & Recovery）**：故障後可回復至一致狀態。
8. **並行控制（Concurrency Control）**：多使用者同時操作而不互相破壞。


* **缺點：**
1. **成本高**：軟硬體、授權費用與專業人員（DBA）成本可觀。
2. **系統複雜**：設計、調校與維護需要專業知識。
3. **效能負擔（Overhead）**：為兼顧安全、一致與並行控制，會犧牲部分效能。
4. **集中化風險**：資料集中導致單點故障（Single Point of Failure），一旦損毀影響範圍大。



### 三. 種類

1. **階層式資料庫**
* 樹狀
* 一對多，1:N
* 以指標沿樹狀路徑存取。
* 結構簡單、查詢快；但無法表達 M:N、結構僵硬、資料易重複。


2. **網路式資料庫**
* 圖狀
* 可M:N
* 以指標連結。
* 較階層式靈活；但結構更複雜、指標維護困難、程式與結構耦合高。


3. **關聯式資料庫**
* 二維表格
* 以「值」（外來鍵）建立表間關聯，而非指標。
* 簡單直覺、理論嚴謹、資料獨立性高、查詢彈性強；但複雜關聯需大量 JOIN、不擅長非結構化資料、大規模水平擴展較難。


4. **物件導向式資料庫**
* 以物件儲存
* 支援封裝、繼承、多型，每個物件有唯一識別碼。
* 直接對應物件導向程式、解決阻抗不匹配、擅長複雜資料；但標準不統一、學習曲線高、市場接受度低。
* *(阻抗不匹配，物件導向程式的「物件」與關聯式的「表格」結構不一致，存取時須來回轉換)*
