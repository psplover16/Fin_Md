分散式架構的物理天花板 —— CAP 定理 (⭐ 申論題 / 選擇題 必考)

分散式系統無法同時滿足以下三點，最多只能「三選二」：

1.  **C (Consistency, 一致性)**：每次讀取都拿到「最新寫入」的資料，否則就報錯（大家看到的資料永遠同步）。
2.  **A (Availability, 可用性)**：每次請求都一定能收到「非錯誤的回應」，但不保證是最新的資料。
3.  **P (Partition Tolerance, 分區容忍性)**：當系統節點之間的「網路斷線」時，系統仍能繼續運作。

> **💡 【考場必寫金句】**<br>
> 「在現代分散式系統中，網路斷線是常態，因此 **P (分區容忍性) 是必須妥協接受的前提**。
<br>設計師只能在 **CP (追求一致性，如 MongoDB、HBase)** 與 **AP (追求高可用性，如 Cassandra、DynamoDB)** 之間做權衡取捨。」

交易原則 —— BASE 特性 (⭐ 申論題 必考對比)

傳統關聯式資料庫 (RDBMS) 遵守 **ACID**，而 NoSQL 為解決效能與擴充問題，改採 **BASE** 原則：

1.  **BA (Basically Available, 基本可用)**：保證系統可用性。
2.  **S (Soft State, 軟狀態)**：允許系統存在「中間狀態」，即使無新寫入，資料狀態也可能因節點間同步而改變（資料允許暫時不同步）。
3.  **E (Eventual Consistency, 最終一致性)**：在無新更新下，系統最終會達到一致。

> **💡 【考場必寫金句】**<br>
> 「NoSQL 放棄了傳統資料庫嚴格的 ACID 剛性一致性，改以 BASE 原則，透過犧牲短暫的資料一致性，換取系統極高的**水平擴充能力** 與效能，達到『最終一致性』。」

## NoSQL 的四大分類與應用 (⭐ 選擇題 秒殺區 / 申論題 舉例區)

| 分類 (Type) | 儲存結構特性 | 代表性軟體 (必背) | 最適合的應用情境 (考點) |
| :------ | :--- | :--- | :--- |
| **1. 鍵值 (Key-Value)** | 最簡單、速度最快。<br>透過唯一 Key 找 Value。<br>只能查詢，無法做複雜關聯。 | ***Redis***, Memcached, DynamoDB | **快取系統 (Cache)**、購物車、Session 儲存。 |
| **2. 文件 (Document)** | 將資料存為 JSON/BSON 格式。<br>Schema-free (無固定結構)，擴充欄位極度彈性。 | ***MongoDB***, CouchDB | **內容管理系統 (CMS)**、部落格、電商商品型錄。 |
| **3. 欄族 (Column-Family)** | 以「欄 (Column)」為單位儲存，適合儲存海量且欄位極多的資料。<br>極高寫入/查詢吞吐量。 | ***Cassandra***, <br>***HBase*** | **物聯網 (IoT) 感測器數據**、海量日誌分析、分散式大數據儲存。 |
| **4. 圖形 (Graph)** | 由節點 (Node) 與邊 (Edge) 組成。<br>專門處理資料之間複雜的「關聯關係」。 | ***Neo4j*** | **社群網路 (誰認識誰)**、推薦系統、地圖導航。 |

## RDBMS vs. NoSQL (⭐ 申論題 必備武器)

若考題問：「何時該用 NoSQL？與關聯式資料庫有何不同？」，請直接列出此比較：

| 比較維度 | 關聯式資料庫 (RDBMS) | NoSQL 資料庫 |
| :--- | :--- | :--- |
| **全名/代表** | 關聯式 (MySQL, Oracle, SQL Server) | Not Only SQL (MongoDB, Redis, Cassandra) |
| **資料結構 (Schema)** | **固定結構 (Rigid)**，須事先定義資料表，修改欄位成本高。 | **動態/無結構 (Schema-free)**，極具彈性，可隨時新增屬性。 |
| **擴充方式 (Scaling)** | **垂直擴展 (Scale-up)**：靠單一伺服器升級 CPU、記憶體。 | **水平擴展 (Scale-out)**：透過增加多台廉價伺服器叢集分擔流量。 |
| **交易特性 (Transaction)**| 遵守嚴格的 **ACID** 原則。 | 遵守 **BASE** 原則 (追求最終一致性)。 |
| **資料表關聯 (Join)** | 支援複雜的 Join 查詢。 | 通常不支援 Join，需靠程式邏輯處理。 |
| **適用場景** | 高價值/高正確性交易（如：**銀行金流**、訂單結帳）。 | 海量資料、高併發讀寫、資料結構常變動（如：**社群媒體**、大數據分析）。 |

---

1.  **破除迷思**：申論題務必點出「**NoSQL 不是用來取代 SQL 的** (Not Only SQL)」。現代系統多採 **Polyglot Persistence（混合持久化策略）**：金流訂單交給 MySQL (ACID)，商品型錄交給 MongoDB (彈性)，熱門商品快取交給 Redis (極速)。寫出這句，閱卷老師會認為你具備實務 Sense。
2.  **解題直覺**：看到「高併發、海量、彈性結構、水平擴充」，無腦選 NoSQL。看到「金融交易、嚴格一致性、複雜 Join」，無腦選 RDBMS。
