# 計算機概論 重點筆記

## 計算機架構與理論基礎

### 馮紐曼架構：
程式和資料都放在同一個記憶體中，通常也共用同一組匯流排，CPU 依照順序一個一個讀取指令並執行。
*   輸入單元、輸出單元、運算器(ALU)、控制器(CU)、記憶體。

### 圖靈機
是一種抽象的計算模型，用來描述「計算」最核心的過程，並研究哪些問題可以被明確的計算程序解決。
*   無限長紙帶、讀寫頭、有限控制器

### 圖靈測試
是用來判斷機器是否展現出類似人類智慧的測試。

## 機器指令與指令週期
**機器指令**：CPU 直接看得懂的二進位命令

**範例**：
*    ADD(R1, R2)：R1、R2 為暫存器
*    LOAD(R1, 1000)：R1為目的暫存器、1000表示位址資訊

**指令週期流程**：
取指令(Fetch) ➔ 解碼(Decode) ➔ 取運算元／算位址(Operand Fetch / Address Calculation) ➔ 執行(Execute) ➔ 寫回(Write Back / Store) <br>
(拿單 ➔ 看懂 ➔ 拿料 ➔ 下鍋 ➔ 裝盤)

*   **Opcode**：要執行的操作
*   **Operand**：被操作的資料、暫存器或位置
*   **Effective Address**：真正要存取的記憶體位置

*   **第一步(取指令)**：
    * PC(程式計數器) → MAR(記憶體位址暫存器)
    * PC + 1 → PC
    * Memory → MDR(記憶體資料暫存器) → IR(指令暫存器)
*   **第二步(算位址)**：IR → Control Unit (解碼並計算 EA(有效位址))
*   **第三步(拿資料)**：
    * EA → MAR
    * Memory → MDR
*   **最後一步(執行)**：ALU 進行運算。

## Pipeline 與 Hazard

### 零、 典型五階段 (Pipeline Stages)

* **核心觀念**：為維持管線化節奏統一，所有指令**一律固定消耗 5 個週期**，不可跳關。若不需要該階段的功能，則在該階段「閒置 (Pass-through)」。
* **五大階段 (`IF > ID > EX > MEM > WB`)**：
1. **IF (Instruction Fetch)**：取指令。
2. **ID (Instruction Decode)**：指令解碼，並讀取暫存器。
3. **EX (Execute)**：ALU 執行運算，或計算有效位址 (EA)。
4. **MEM (Memory Access)**：存取主記憶體資料 (Load/Store)。
5. **WB (Write Back)**：將結果寫回暫存器。


* **實例對照**：
* **例 1（記憶體存取指令：`LOAD`）**
【IF 拿指令】➔【ID 解碼】➔【EX 算出確切記憶體位址】➔**【MEM 去記憶體把資料拿出來 (實質運作)】**➔【WB 將資料放進暫存器】。
* **例 2（算術運算指令：`ADD`）**
【IF 拿指令】➔【ID 讀取兩個數字】➔【EX 算出加法答案】➔**【MEM 發呆空轉一圈 (閒置路過)】**➔【WB 將答案放進暫存器】。

### 一、 管線化基礎與效能極限

* **核心運作**：管線化的時脈週期時間，由**耗時最長的階層**決定。
* **執行時間公式**（假設 n 個指令、k 個階層、週期時間 t）：
* 非管線化總時間 = n * k * t
* 管線化總時間 = (k + n - 1) * t

* **效能極限與突破**：
* **傳統極限**：理想 CPI = 1（因單一週期最多只能發行 1 個指令）。
* **超純量架構 (Superscalar)**：打破極限使 **CPI < 1**。機制是讓 CPU 在單一週期內，將多道指令分發到多個獨立執行單元進行並行運算。


### 二、 管線化三大危險 (Hazards)

**1. 結構危險 (Structural Hazard)**

* **起因**：硬體資源不足。最常考的是 `IF` (取指令) 與 `MEM` (存取資料) 階段同時搶用同一塊記憶體。
* **解法**：
    *   **完美解 (硬體)**：採用**哈佛架構 (Harvard Architecture)**，將指令快取與資料快取實體分離。
    *   **替代解**：若無哈佛架構，只能插入氣泡暫停 (Stall)。

**2. 資料危險 (Data Hazard)**

* **起因**：指令間存在相依性。後續指令需要前面指令「尚未寫回暫存器」的資料（即 RAW 相依）。
* **解法**：
    *   **完美解**：**前饋機制 (Forwarding / Bypassing)**。不寫回暫存器，直接從 ALU 將運算結果拉線給下一個指令。
    *   **Load-Use Hazard**：當 `LOAD` 指令後面「緊接」需要該資料的指令時，即使有前饋機制，仍必須強制暫停 (Stall) 1 個週期。
        *   指令1 (LOAD 取資料)：IF ➔ ID ➔ EX ➔ MEM (在這裡的最後，才真正拿到資料) ➔ WB
        *   指令2 (ADD 加法) ：    IF ➔ ID ➔ EX (在這裡的一開始，就需要資料來算) ➔ MEM ➔ WB

**3. 控制危險 (Control Hazard)**

* **起因**：遇到分支跳躍指令 (Branch) 時，CPU 不確定下一道指令的位址，導致抓錯指令。
* **解法**：
    *   **硬體解 (分支預測)**：搭配**分支目標緩衝器 (BTB)**，記住上次跳躍的目標位址，直接抄捷徑免重新計算。
    *   **軟體解 (分支延遲槽, Delay Slot)**：編譯器刻意在分支指令後方，放入「無論有沒有跳躍都必須執行」的指令，以榨取管線效能。


* **代價**：只要分支預測猜錯，管線必須將提早拿進來的錯誤指令全部**沖刷 (Flush)** 作廢。


### 三、 實際效能計算 (必背公式)

* **停頓週期** = 分支指令比例 * 預測錯誤率 * 錯誤懲罰週期 (Penalty)
* **實際 CPI** = 理想 CPI + 停頓週期 (Stall Cycles)

## RISC VS CISC (代表架構主要背誦CISC、RISC只要知道ARM即可)
*   **CISC**：指令複雜，硬體線路難做且難除錯，改以微程式(ROM存微碼)翻譯執行。
    *   CISC：指令繁，IC↓、CPI↑ (不規則)
    *   CISC 代表架構：x86 (Intel/AMD)、VAX、PDP、Motorola 68000 (M68K)、IBM 360/370
*   **RISC**：指令簡，IC↑、CPI↓ (接近1)
    *   RISC 代表架構：ARM (手機), RISC-V (開源架構), MIPS, SPARC, PowerPC

## 效能評估
*   CPU 執行時間
    *   `CPU Time = Instruction Count × CPI(每指令平均週期數) × Clock Cycle Time(時脈週期時間)`
    *   `CPU Time = Instruction Count × CPI / Clock Rate`
*   MIPS (每秒執行百萬指令)，數值越大越好
    *   `MIPS = Instruction Count / (Execution Time × 10^6)`
    *   `MIPS = Clock Rate / (CPI × 10^6)`

## 匯流排
*   **位址匯流排**：找位置，單向 (CPU → 記憶體或 I/O)，都是由他先動作。
*   **控制匯流排**：管動作，雙向
*   **資料匯流排**：送內容，雙向
*   **位址 (找哪裡) ➔ 控制 (做什麼) ➔ 資料 (搬東西)**
*   n bits 位址匯流排可產生 2^n 個位址。
*   若每個位址代表 1 byte，則可定址空間為 2^n bytes。
*   n bits 資料匯流排一次可傳送 n bits 的資料。

## 記憶體階層與特性
暫存器 Register → L1 Cache → L2 Cache → L3 Cache → 主記憶體 Main Memory / RAM → SSD / HDD → 外部儲存 External Storage
*   **時間區域性(Temporal Locality)**：同一個資料很快又用一次 (迴圈)
*   **空間區域性(Spatial Locality)**：用到某位置後，附近位置也會用 (陣列)

### 記憶體種類
*   **RAM**：執行中、可快讀寫、斷電多消失。
*   **ROM**：放韌體、放開機程式、斷電多保留。
*   **SRAM**：靜態隨機存取記憶體。正反器構成。不需週期性充電，只要通電資料就在。貴、小、快。專做CPU快取記憶體(Cache)。
*   **DRAM**：動態隨機存取記憶體。電容與電晶體構成。電容會漏電，必須週期性充電才能保存資料。便宜、大、慢。專做系統主記憶體(RAM)。

### ROM 種類
*   **PROM**：高電壓燒斷內部保險絲、只能寫入一次、寫錯即報廢。
*   **EPROM**：紫外線照射石英視窗、須拔下晶片、可整片擦除後再燒錄、不方便。
*   **EEPROM**：電壓訊號線上抹除、不需拔晶片、以Byte為單位局部改寫、速度慢、存BIOS。
*   **Flash**：電壓訊號、以Block為單位整塊快速擦寫、容量大成本低、做SSD與隨身碟。

### 暫存器(Register)
CPU內部極小極快的儲存空間。
*   **PC(程式計數器)**：存放下一個要執行的指令位址。
*   **IR(指令暫存器)**：存放目前正在執行的指令。
*   **Base Register(基底暫存器)**：存放程式記憶體區段起始位址。
*   **Limit Register(界限暫存器)**：存放程式可用區段大小。
*   **MAR(記憶體位址暫存器)**：存放要存取的記憶體位址。
*   **MDR(記憶體資料暫存器)**：存放準備讀寫的資料。
*   **Flag Register(旗標暫存器)**：記錄運算結果狀態(如零、進位、溢位)。
*   **AC(累加器)**：暫存ALU運算的中間或最終結果。

### 快取 (Cache) 機制
*   **AMAT公式**：命中時間 + 未命中率 * 懲罰時間
*   **Cache 在面對「寫入 (Write)」動作**：
    *   **命中 (Write Hit) 策略**，當 CPU 要寫入的資料已經存在於 Cache 中：
        *   Write Through：同步寫入Cache與主記憶體
        *   Write Back：先寫Cache，替換時才寫回主記憶體
    *   **未命中 (Write Miss) 策略**，當 CPU 要寫入的資料不在 Cache 中：
        *   Write Allocate (寫入配置)：未命中先載入Cache再寫入。適合反覆存取。
        *   No Write Allocate (非寫入配置)：未命中直接寫下層，不載入Cache。避免占空間。

## 數位邏輯與資料表示

### 進制轉換
*   10進制轉2進制，
    * 整數部分採連除法，每次除以2，取餘數，由下至上。
    * 小數部分採連乘法，取商，由上至下。
*   2進制轉8進制，小數點做區隔，小數點往左，每三分切一份；小數點往右，每三分切一份。

### 補數
補數是電腦用固定 bits 表示正負整數的方法
*   **1補數**，01互換，±0，-(2^(n-1)-1) 到 +(2^(n-1)-1)
*   **2補數**，01互換+1，**無-0**，-2^(n-1) 到 +(2^(n-1)-1)

### 浮點數
符號位S / 指數欄位E / 尾數欄位M / 偏移值(用來計算指數欄位用)
*   單精度： 1 / 8 / 23 / 127
*   雙精度： 1 / 11 / 52 / 1023
*   範例：18.75(10) 單經度浮點數計算
    1. 先把18.75(10) 轉乘 10010.11(2)
    2. 10010.11 = 1.001011*2^4
    3. 決定 1 bit 符號位：
        * 原數字若是正數，S = 0；如果是負數則為 1
    4. 計算 8 bits 指數位 (Exponent, E)
        1. 取 2^4 的 **4** 
        2. **4 + 127 = 131(10)**
        3. 131(10) = 10000011(2)
        4. 指數位 = 10000011
    5. 提取 23 bits 尾數位：
        * 1.001011 把 小數點前的數字去掉，往右邊補0，直到湊滿 23 個位元
    6. S + E + M = 0 10000011 00101100000000000000000

### 數碼
*   **BCD(8421碼)**：4個bit對應1個十進位數字。範圍0000到1001。數字個別拆開轉換
    * 259 → 0010 0101 1001
*   **Gray Code(葛雷碼)**：相鄰兩碼只差1個bit。用途為位置偵測、降低切換讀錯率。
    *   ⊕ 表示 XOR，互斥或，輸入不同輸出1
    *   Binary轉Gray：只看Binary，最高位照抄。 **目前 Gray = 左邊 Binary ⊕ 目前 Binary**
        * Binary 1011 = Gray 1110
    *   Gray轉Binary：最高位照抄。 **目前 Binary = 左邊 Binary ⊕ 目前 Gray**
        * Gray 1110 = Binary 1011

### 文字碼細節
*   **ASCII**：7 bits，存128種字(英數與控制字元)。
*   **Extended ASCII**：8 bits，存256種字。
*   **EBCDIC**：8 bits，IBM與大型主機專用。
*   **Unicode**：全球統一語言的"字元碼位編號"(是概念字典，不是實體存檔格式)。
*   **UTF-8**：把 Unicode 編號存成 bytes 的**方式**(1到4 bytes)。特色是完全相容ASCII(0~127同樣用1 byte存)。

### 錯誤偵測與校正
*   **Parity Check（同位元檢查）**：只偵錯，不糾錯
    *   偶同位（Even Parity）： 加上檢查位後，1 的總數為偶數
    *   奇同位（Odd Parity）： 加上檢查位後，1 的總數為奇數
*   **CRC(循環冗餘校驗)**：只偵錯，不糾錯
    1.  CRC 位數(r) = 生成多項式長度 − 1。
    2.  在資料位元串後方，添加 r 個0
    3.  把第二步驟取得的數字 從左至右，分別與 生成多項式 XOR，餘數為CRC。
    *   資料位元串 + CRC = 訊框
    *   ex. 欲傳送資料為 1101，生成多項式 (Generator) 為 $X^3 + X + 1$。請問附加 CRC 後，最終送出的完整資料為何 ? 
        * 1101101
*   **漢明碼**： 錯誤偵測與「糾正」
    1.  2^r ≧ m+r-1，m是原始資料位數、r為漢明碼校驗位
    2.  漢明碼 驗證，檢查通過記 0，失敗記 1 ，然後倒過來看
    *   ex. 欲傳送 4 位元資料 1011，若採用偶同位 (Even Parity) 漢明碼，請寫出完整的 7 位元編碼。
        1. 畫出 7 個空格，標示檢查碼位置，P1、P2、P4 是檢查碼： <br>
        [位置]：P1 | P2 | D1 | P4 | D2 | D3 | D4 <br>
        [代表]：001| 010| 011| 100| 101| 110| 111<br>
        [資料]：P1 | P2 | 1 | P4 | 0 | 1 | 1
        2. P1、P2、P4 分別代表 001、010、100，那分別管理數字當中有包含的位數
            * P1：管 1, 3, 5, 7 格 ➔ 內容是 (P1, 1, 0, 1)。為湊偶數個 1 ➔ P1 = 0    
            * P2：管 2, 3, 6, 7 格 ➔ 內容是 (P2, 1, 1, 1)。為湊偶數個 1 ➔ P2 = 1
            * P4：管 4, 5, 6, 7 格 ➔ 內容是 (P4, 0, 1, 1)。為湊偶數個 1 ➔ P4 = 0
        3. 完整漢明碼為 **0110011**
    *   ex. 0110111 (採偶同位) 檢查錯誤
        1. 把收到的資料填入 1~7 的位置 <br>
        [位置]：1 | 2 | 3 | 4 | 5 | 6 | 7 <br>
        [資料]：0 | 1 | 1 | 0 | 1 | 1 | 1
        2. 重新分組檢查，算出「錯誤碼 (Syndrome)」
            * P1：管 1, 3, 5, 7 格 ➔ 內容是 (0, 1, 1, 1)。共有三個 1 (奇數) ➔ 有錯，C1 = 1
            * P2：管 2, 3, 6, 7 格 ➔ 內容是 (1, 1, 1, 1)。共有四個 1 (偶數) ➔ 沒錯，C2 = 0
            * P4：管 4, 5, 6, 7 格 ➔ 內容是 (0, 1, 1, 1)。共有三個 1 (奇數) ➔ 有錯，C4 = 1
        4. 將錯誤碼倒過來排，轉成十進位
            * (C4, C2, C1) ➔ 101(2) ➔ 5(10)

*   **漢明距**，兩個碼字不同bit的數量
    *   漢明距：兩個長度相同的二進位編碼中，「對應位置位元不同」的總個數。
    *   Dmin = 最小漢明距
    *   偵測 d 個錯誤 Dmin >= d + 1
    *   更正 t 個錯誤 Dmin >= 2t + 1

## 系統效能與排班

### 阿姆達爾定律
*   f：可改善部分占原本時間的比例
*   s：那部分加速幾倍
*   整體加速比 = 原時間 ÷ 改善後時間 = `1 ÷ ( (1 − f) + f ÷ s )`

### 作業系統的排班
| 排班層級 | 別名 | 在做什麼 | 執行頻率 |
| :--- | :--- | :--- | :--- |
| 長程排班 | 工作排班器 | 決定哪些工作可進入系統 | 最低 |
| 中程排班 | — | 把程序換出/換入記憶體 (swap) | 中 |
| 短程排班 | CPU 排班器 | 決定誰下一個用 CPU | 最高 |

*   **短程排班(Short-term Scheduling)**：OS核心決定就緒佇列(Ready Queue)中，何者取得CPU執行權的資源分配機制。
*   **1. 甘特圖**就是一條「時間軸」：由左到右代表時間流動,上面用一塊一塊標出「每個時間點是誰在用 CPU」
*   **2. 最佳化目標**：最大化CPU使用率與產能；最小化等待、迴轉與回應時間。
*   **3. 就緒佇列（Ready Queue）**：已到達、等 CPU 的隊伍。
*   **4. 到達時間（Arrival Time）**：程序進入**就緒佇列**的時間**點**。
*   **5. 完成時間 (Completion Time)**：行程全部做完、離開系統的時間**點**。

*   **6. 執行時間（Burst Time）**：程序實際需要佔用 **CPU 運算的總時間**。
*   **7. 迴轉時間(Turnaround Time)**：待在系統內的總時間。 
    * **完成時間 - 到達時間**
    * **等待時間 + 執行時間**
*   **8. 等待時間 (Waiting Time)**：程序於就緒佇列中，等待獲取CPU分配的**總累積時間**。
    * **迴轉時間 - 執行時間**
*   **9. 回應時間(Response Time)**：從到達開始，「第一次拿到 CPU 開始做事」的時間差。為分時系統衡量互動性的關鍵指標。 
    * **首次獲取CPU時間 - 到達時間**

### 系統類型
*   **批次系統 (Batch System)**：將性質類似的工作收集成一個「批次」，一次交給電腦處理，過程中不需要使用者介入互動（例如：銀行半夜結算當天報表、大型科學運算）。因為不需要互動，使用者只在乎「總共要花多久時間做完」，因此最重要的指標是迴轉時間 (Turnaround Time) 與產能 (Throughput)。
*   **互動系統 (Interactive System)**：使用者會不斷與系統進行對話與操作，系統必須快速給予回饋（例如：我們日常使用的 Windows/macOS、網頁伺服器）。也常被稱為分時系統 (Time-Sharing System)。使用者無法忍受點擊滑鼠後畫面卡住，因此最重要的指標是回應時間 (Response Time)。
*   **分時系統 (Time-Sharing System)**： 就像我們現在用的 Windows 或 macOS，強調讓使用者覺得電腦「同時」在處理很多事，且能即時互動。

### 搶占與不可搶占
*   **不可搶占(Non-preemptive)**：程序獲取CPU後將持續執行至自願釋放或終止，OS無法強制剝奪其控制權。
*   **可搶占(Preemptive)**：OS可依據中斷、優先權或時間限制，強制回收當前程序的CPU控制權，此過程必定引發上下文切換(Context Switch)。
    * 可搶佔的流程：執行中 (Running) → 強制踢回 → 就緒 (Ready) → 再次分配到 CPU → 執行中 (Running)
    * 在 "就緒"會觸發的排班，就是可搶占。

### 經典排班演算法
1.  **FCFS 先到先服務 (First-Come, First-Served)**，不可搶占。
    *   護航效應 (Convoy Effect)，容易因為超長程序排在前面，而造成堵塞。
2.  **SJF 最短工作優先 (Shortest Job First)**，不可搶占。
    *   規則：每次 CPU 空出來時，從「已到達」的程序裡挑 Burst 最短的先做。
    *   最大優點(必考)：在所有排班法中，SJF 給出的平均等待時間最小(理論最佳值)。
    *   缺點 1——無法預知：實務上難以準確預估執行時間(Burst Time)，只能用過去紀錄「估計」。
    *   缺點 2——飢餓 (Starvation)：短程序一直進來，某個長程序可能永遠輪不到。
3.  **SRTF 最短剩餘時間優先 (Shortest Remaining Time First)**：SJF的可搶占版本。
    *   規則：跟 SJF 一樣挑最短，但只要新來程序所需時間 < 目前程序的剩餘時間，觸發搶占。平均等待時間低於SJF。
    *   缺點 1——頻繁搶占會導致甚高的上下文切換成本。
    *   缺點 2——仍有飢餓問題。
4.  **Priority(優先權排班)**：可搶占或不可搶占。
    *   規則：每個程序給一個優先權數字，優先權高者先做。
    *   與 SJF 的關係(考點)：SJF 是 Priority 的特例。把「Burst 越短 = 優先權越高」就是 SJF。
    *   缺點——飢餓 (Starvation)：低優先權程序可能一直被插隊，永遠做不到。
    *   解法——老化 (Aging)：程序等越久，就慢慢自動「升優先權」，等到夠久一定會被排到。
5.  **Round Robin 輪轉法 (RR)**，適合分時/互動系統。
    *   規則：給每個程序一段固定的"時間量子" (Time Quantum / Time Slice)，輪流做，做不完往最後排隊。
    *   優點：公平、沒有飢餓、回應時間短(每個人很快被叫到)。
    *   量子設太大 → 大到每個程序一次就做完 → 退化成 FCFS。
    *   量子設太小 → 一直在換程序，上下文切換 (Context Switch) 成本爆高，效率變差。
6.  **MLQ 多層佇列 (Multilevel Queue)**
    *   程序不可跨層移動。
    *   依程序屬性(如系統、互動、批次)靜態劃分至不同佇列。
    *   存在絕對優先權壓制，低層佇列發生飢餓機率極高。
7.  **MLFQ 多層回饋佇列 (Multilevel Feedback Queue)**：程序可跨層移動，內含動態優先權調整。
    *   程序若耗盡時間量子則降級，若等待過久則觸發老化機制升級。
    *   為現代OS最常採用之綜合型高彈性排班法。

## 死結 (Deadlock)

### 死結四條件，缺一不可：
*   **互斥(Mutual Exclusion)**：資源一次只能一個程序用，不能共用。
*   **持有並等待(Hold and Wait)**：抓著手上資源不放，同時又在等別的資源。
*   **不可搶占(No Preemption)**：資源不能被強行搶走，只能由持有者自願釋放。
*   **循環等待(Circular Wait)**：等待關係繞成一個環(A 等 B、B 等 C、C 等 A)。

### 處理策略
*   **預防(Prevention)**，破壞四條件，資源利用率極低、效能差。
*   **避免(Avoidance)**，系統在分配資源前會需要 最大需求，利用 銀行家演算法 來模擬，確認未來依然安全且不會引發死結後，才會核准請求。
*   **偵測復原(Detection)**，放任死結發生。事後處理、有開銷。等待圖 / 偵測演算法。
*   **鴕鳥(Ostrich)**，不處理死結。真實 OS 常用。

### 銀行家演算法：
安全性演算法 + 資源請求演算法。如果系統現在有資源，但銀行家演算法卻不准你拿，就是因為拿了會進入不安全狀態。因為不安全狀態是假設程序會要求『最大需求 (Max)』的最壞情況；只要實際執行時，程序沒有同時索取最大資源，就不會死結。
0.  算出 各程序的 Need (需求) = Max (最多需要) - Allocation (已借出)
    以及需要知道 Available (目前庫存)。
1.  **安全性演算法 (找安全序列)**，拿 Available (庫存) 去與 各程序的 Need (需求) 比較。可以滿足地就執行，然後回收資源。
2.  **資源請求演算法 (動態審核)**：專門用在「某個程序在執行過程中(p0)」，突然要求資源
    *   2-1. 申請量 不超過 當初說的最大需求
    *   2-2. 目前有足夠的資源可以提供
    *   2-3. 滿足2-1與2-2，試配置後再跑安全演算法。系統「假裝」答應 p0的要求，然後更新帳本。(p0的Allocation增加、p0需求減少、新的 Available減少)

## 分頁與分段記憶體管理

### 1. 基本觀念
1-1. **邏輯位址 (Logical Address) / 虛擬位址 (Virtual Address)**：程式自己看到的位址，從 0 開始編。程式以為自己獨佔整片連續的記憶體。
1-2. **實體位址 (Physical Address)**：資料真正放在實體記憶體 (RAM) 上的位址。
1-3. **MMU (Memory Management Unit, 記憶體管理單元)**：一個硬體，負責在程式執行時，將邏輯位址即時轉換為實體位址。

### 2. 分頁系統 (Paging) 空間等大、離散存放
2-0. **核心概念**：
1. 頁 (Page)：邏輯記憶體（程式）切成固定大小的小塊。
2. 頁框 (Frame)：實體記憶體 (RAM) 切成同樣大小的小格。
3. 頁表 (Page Table)：記錄「第幾頁 -> 放在第幾個頁框」的對照表，每個程序擁有一份。
4. 延伸考點（多層頁表）：若邏輯空間極大，單層頁表本身會佔用過多記憶體。此時會採用多層頁表 (Multi-level Paging)，將頁表分級，需要時才載入以節省空間。
2-1. **有 內部碎裂 (Internal Fragmentation)**：配置出去的記憶體空間比實際需要的大，多出來、用不到的部分在內部被浪費掉了（平均每個程序浪費約半頁）。
2-2. **位址翻譯 (Address Translation)**：
5. 邏輯位址 = [ 頁號 p | 頁內偏移 d ]
6. 實體位址 = [ 框號 f | 頁內偏移 d ] （其中偏移 d 直接照抄）。
7. 原理說明：因為「頁大小 = 頁框大小」，資料搬移前後在格子裡的相對位置（偏移量）完全不會變，這也是偏移量能直接照抄的根本原因。
2-3. **位元 (Bits) 分配與計算公式**：
8. 偏移 bits (offset)：由「頁大小（或頁框大小）」決定。若大小為 2的n次方 bytes，則偏移為 n bits。頁面大小 (Page Size) 絕對是 2 的次方。如果不給「頁大小」只給「頁數」，則 頁號 bits 是由「頁數」決定的（例如有 2^m 個頁，就需要 m 個 bits 來表示頁號）。
9. 頁號 bits：由「邏輯位址空間大小（或邏輯位址總位元數）」決定。
10. 框號 bits：由「實體記憶體空間大小（實體 RAM 大小）」決定。
2-4. **TLB (Translation Look-aside Buffer, 轉譯後備緩衝區)**：
11. 一塊極快的小快取，專門存「最近用過的 頁號 -> 頁框號」對照。
12. TLB 命中 (hit)：要找的頁號在 TLB 裡 -> 直接拿到頁框號，僅需存取 1 次記憶體（直接讀資料）。
13. TLB 未命中 (miss)：TLB 裡沒有 -> 必須先去記憶體讀頁表拿到頁框號，再去讀資料，共需存取 2 次記憶體。
14. 有效存取時間 (EAT) = 命中率 * 命中所需時間 (讀資料 + 查TLB) + 未命中率 * 未命中所需時間 (讀資料 + 讀頁表 + 查TLB)
2-5. **頁表項目 (Page Table Entry)**：
15. 頁框號 (Frame Number)，告訴硬體這個邏輯頁目前被存放在實體記憶體的哪一個框號裡。
16. 有效/無效位元 (Valid / Invalid Bit)：Valid (1)：資料已經在 RAM 裡面，可以安全讀取。Invalid (0)：資料還在硬碟裡，這時候硬體會馬上發出一個中斷，稱為 "Page Fault (分頁錯誤)"，叫作業系統去硬碟把資料搬進 RAM。
17. 保護位元 (Protection / Access Bits)，分頁系統的「保護機制」，控制這個頁的存取權限。通常包含 R (唯讀 Read)、W (可寫入 Write)、X (可執行 Execute)。
18. 髒位元 / 修改位元 (Dirty / Modified Bit)，記錄這個頁自從被載入記憶體後，「有沒有被修改過」。
19. 參考位元 / 存取位元 (Reference / Accessed Bit)，記錄這個頁「最近有沒有被使用過」（不管是讀取還是寫入）。

### 3. 分段系統 (Segmentation) 依邏輯切塊、大小不一
3-0. **核心概念**：按照程式的邏輯單位（例如 main、function、stack）來切，每段大小不一。
3-1. **有 外部碎裂 (External Fragmentation)**：空閒的記憶體總容量足夠，但因為被切成零碎、不連續的小塊，導致無法滿足一個較大的連續記憶體需求。
3-2. **段表 (Segment Table)**：
1. 基底 (Base)：該段在實體記憶體中的起始位址。
2. 界限 (Limit)：該段的長度（有多大）。
3-3. **位址翻譯與保護機制**：
3. 邏輯位址 = [ 段號 s | 段內偏移 d ]
4. 檢查步驟：拿段號，查段表，拿到該段的 base 與 limit。
5. 安全性檢查：檢查 d < limit（超重要考點：是小於而非小於等於，若 d = limit 即為超界）。(因為從0開始)
6. 若檢查未通過，硬體會發出「段錯誤 (Segmentation Fault / Trap)」中斷程式。
7. 若通過，則 實體位址 = base + d（相加得出，不可照抄）。 

### 4. 緊縮 (Compaction)
4-1. **目的**：為了解決分段系統產生的外部碎裂。
4-2. **做法**：將目前正在使用、散落在記憶體各處的「段」全部搬移到記憶體的一邊，使它們緊緊靠在一起，將原本零碎的小空洞合併成一整塊連續的大空間。
4-3. **前提**：程式在執行期間必須是可動態重定位的 (Dynamic Relocatable)。
4-4. **缺點**：搬移大量記憶體資料的系統成本與時間極高。

### 5. 分頁 vs 分段 核心對比
5-1. 切割單位：分頁為固定大小（不管程式邏輯）；分段為邏輯單位（大小不一）
5-2. 碎裂類型：分頁有內部碎裂（無外部碎裂）；分段有外部碎裂（無內部碎裂）
5-3. 重定位法：分頁為「框號 * 框大小 + 偏移（偏移照抄）」；分段為「基底 (Base) + 偏移（相加）」
5-4. 對程式設計師的可見性：分頁為透明 (Transparent)（由硬體處理）；分段為可見 (Visible)（依程式結構規劃）
5-5. 對照表記錄欄位：分頁僅記錄「框號」；分段記錄「Base」與「Limit」
5-6. 解決碎裂方案：分頁無外部碎裂，不需處理；分段可透過緊縮 (Compaction) 解決
5-7. 觀念口訣：分段外、分頁內

### 6. 段頁式記憶體管理 (Paged Segmentation)
6-1. **核心概念**：外層採用「分段」符合程式邏輯，底層採用「分頁」進行實體配置。是實務上最常用的折衷方案。
6-2. 邏輯位址 = [ 段號 s | 頁號 p | 頁內偏移 d ]
6-3. **位址翻譯步驟**：
1. 用段號 s 查「段表」，找到該段專屬的「頁表」起始位址。段頁式的段表：[頁表指標 (Page Table Base) | 頁表長度/段的界限 (Page Table Length)]
2. 用頁號 p 查該「頁表」，換成實體「框號」。
3. 實體位址 = 框號 * 框大小 + 偏移 d。
6-4. **優點**：
4. 保留了分段的邏輯共享與保護機制。
5. 徹底解決了外部碎裂問題（因為底層實體配置依然是等大的分頁，不需連續擺放）。
6-5. **缺點**：記憶體存取延遲大幅增加（查表次數變多）」以及「硬體設計複雜度變高」，所以極度依賴 TLB

## 物件導向四大特性 (OOP 4 Pillars) 
### 1. 封裝 (Encapsulation)
1. 將「資料（屬性）」與「方法（行為）」綁定在一起成為一個類別，並隱藏內部實作細節，只對外開放必要的操作介面。
    *   **資訊隱藏 (Information Hiding)**：避免外部程式碼直接竄改內部資料，保護資料完整性與安全性。
    *   **補充**：實務上通常將屬性設為 private，並透過公開的 Getter / Setter 方法來存取，以便在方法內加入邏輯判斷（例如：年齡不能設定為負數）。
2. **存取修飾子比較 (嚴格 -> 寬鬆)**：
    *   `private`：只有「同一個類別內」能存取。
    *   `default`：不寫修飾子即為此模式（套件私有）。「同一個套件內」的類別都能存取，跨套件不行。
    *   `protected`：在 default 之上，再多開放給「其他套件的子類別」存取。
    *   `public`：任何地方都能存取。

### 2. 繼承 (Inheritance)
1. 讓一個新類別（子類別）直接擁有既有類別（父類別）的屬性和方法，達到程式碼重用 (Code Reusability) 的目的。
2. 不必重寫既有功能，還能擴充自己的新功能，或修改（覆寫）父類別行為。
    *   **關係設計**：繼承 = `is-a` (例如：狗「是一種」動物)；組合 = `has-a` (例如：車子「有一個」引擎，要用組合 Composition)。(註：實務常提倡「多用組合，少用繼承」以降低耦合度)
    *   **語言差異**：Java 不支援類別多重繼承（用介面替代）；C++ 支援。
    *   **補充**：子類別無法繼承父類別的 private 成員與建構子，但可透過 `super()` 呼叫父類別建構子。

### 3. 多型 (Polymorphism)
1. 同一個方法名稱（同一個訊息），套在不同物件上，會有不同的行為與執行結果。    
2. 兩大實現方式：
    1. **多載 / 重載 (Overloading)** —— 編譯期多型：同一個類別裡，有多個同名方法，靠「參數不同」(個數、型別、順序) 來區分。
    2. **覆寫 (Overriding)** —— 執行期多型：子類別把父類別「已經有」的方法重新定義一次 (方法簽章必須完全相同)。

### 4. 抽象 (Abstraction)
1. 抽取出物件重要、共通的特徵，隱藏不必要的實作細節，只對外呈現必要的介面（做什麼 What，而非怎麼做 How）。
2. **實作方法比較：抽象類別 (Abstract Class) VS 介面 (Interface)**，兩者皆不能直接實例化 (new 出物件)。    
    1. 設計意義：抽象類別：`is-a` (你本質是什麼)，提供共通的基礎實作，用來避免程式碼重複。介面：`can-do` (你能做什麼)，定義行為規範或能力契約，不關心物件實際內容。
    2. 繼承限制 (JAVA及C#)：抽象類別：只能繼承一個 (`extends`)。介面：可實作多個 (`implements`)。
    3. 方法實作：抽象類別：可同時有「已實作方法」與「抽象方法」。介面：傳統只能有宣告(無實作)；Java 8+ 支援 default/static 已實作方法。
    4. 變數狀態：抽象類別：可有一般變數，保有物件狀態。介面：只能是常數 (`public static final`)，無狀態。
    5. 建構子：抽象類別：有建構子 (供子類別 super 呼叫初始化)。介面：無建構子。

```java
public abstract class Animal {
    // 1. 可有一般變數
    protected String name;

    // 2. 可有建構子
    public Animal(String name) {
        this.name = name;
    }

    // 3. 抽象方法 (只宣告，無實作)
    public abstract void makeSound();
}

// 2. 介面 (Interface)
public interface Flyable {
    // 1. 只能是常數
    int MAX_SPEED = 100; 

    // 2. 抽象方法 (只宣告，無實作)
    void fly(); 
}

// 3. 子類別繼承與實作
public class Bird extends Animal implements Flyable {    
    // 必須呼叫父類別的建構子來初始化一般變數
    public Bird(String name) {
        // 呼叫父類別建構子
        super(name);
        // super.方法名稱() ：呼叫父類別的「一般方法」
    }

    // 實作 Animal(抽象類別) 規定的方法
    @Override
    public void makeSound() {
        System.out.println(name + " 說：啾啾！");
    }

    // 實作 Flyable(介面) 規定的方法
    @Override
    public void fly() {
        System.out.println(name + " 正在飛翔，最高時速：" + MAX_SPEED);
    }
}
```

## 雜湊表
1. 透過將「Key(鍵)」導入「Hash Function(雜湊函數)」，得到「Bucket / Slot(儲存格)」
2. 時間複雜度，平均情況 O(1)；但若嚴重碰撞，則 O(n)
3. 雜湊函數設計法 (k為關鍵字、m為雜湊表大小)：
    1. **除算法 (Division Method)**：h(k) = k mod m。將關鍵字 k 除以雜湊表大小 m，取其餘數作為索引。考點: m 建議選擇「質數」，能讓資料分布更均勻，減少碰撞。
    2. **乘算法 (Multiplication Method)**：h(k) =  ⌊ m * (k * A mod 1) ⌋。透過常數A與k相乘，提取小數部分後，再乘以m，最後將其無條件捨去所有小數部分。常數A有限制，0 < A < 1。
    3. **平方取中法 (Mid-Square Method)**：將關鍵字 k 平方，擷取中間位數作為索引。範例，設 m = 100 (需兩位數 Index，因為0~99)，k = 45。計算:45² = 2025 → 取中間兩位數 02。Index 2。
    4. **摺疊法 (Folding Method)**：將長度較長的關鍵字 k 切割為數個等長的片段，將這些片段的數值相加。若加總後的結果大於雜湊表大小 m，則再取餘數。範例，設 m = 1000 (需三位數)，k = 12345678 -> 12 + 345 + 678 = 1035 -> 1035 mod 1000 = 35 (索引為 35)。
4. 載入因子與重新雜湊：
    0. 資料變多，載入因子越高；高到指定的數值，重新雜湊
    1. **載入因子 (Load Factor, α)**，用來評估雜湊表「有多擠」的指標。α = 目前儲存的資料總數 / 雜湊表的總格數
    2. **重新雜湊（Rehashing）**：擴大表格，兩倍大並尋找下一個質數；改變雜湊函數 (因為表格變大)；重新計算與搬移，BigO為 O(n)。
5. 碰撞，有兩大處理方式：
    1. **鏈結法 (Chaining)**，將資料串接在同一個儲存格的鏈結串列(Linked List)上。不會有「找不到空位」的問題。(指標集合庫)
    2. **開放定址法 (Open Addressing)** (實體資料集合庫)：
        1. **線性探測法 (Linear Probing)**：h_i(k) = (h(k) + i) mod m。H(k, i) 經過第 i 次碰撞探測後，鍵值 k 最終被決定存入的雜湊表索引位置，i 代表探測次數（Probe Number）。易產生主要/初級聚集 (Primary Clustering)。資料會一堆聚集再一起。
        2. **二次探測法 (Quadratic Probing)**：h_i(k) = (h(k) + i^2) mod m。解決主要聚集，但會產生次要/二級聚集 (Secondary Clustering)。資料會「規律性」且「固定路徑」的碰撞。
        3. **雙重雜湊法 (Double Hashing)**：h_i(k) = (h_1(k) + i * h_2(k)) mod m。第0次碰撞，只會有 h_1(k) mod m。效果最好。h_2(k) 絕對不能為 0，且必須與 m 互質(最大公因數為1)。
6. 墓碑機制：
    1. 開放定址法的刪除：若直接刪除，會導致「搜尋鏈結斷裂」，必須採用 墓碑機制。
    2. 使用「Deleted（已刪除，俗稱墓碑）」取代「Empty（空）」。
    3. 缺點：
        1. 墓碑污染 (Tombstone Contamination / Pollution)：太多無效的已刪除標記，導致空間看起來很滿，但實際有效資料很少。
        2. 探測長度增加 (Increased Probe Length)：系統為了找到目標或空位，平均需要跳躍與檢查的步數變多了。
        3. 效能退化 (Performance Degradation)：整體搜尋時間複雜度，因為充滿墓碑，逐漸從 O(1) 退化向 O(n) 的狀態。
7. 探測（Probe），總共 檢查陣列中的位置數量。預期探測次數：α 是載入因子，也就是目前雜湊表有資料的比例。
    1. 鏈結法：搜尋失敗：1 + α (打開櫃子，每一個都檢查一遍)；搜尋成功：1 + α/2 (打開櫃子 + 最快在第1個，最慢在最後，取平均)。
    2. 開放定址法：搜尋失敗：1 / (1 - α)，α越接近1，表示雜湊表越滿，也越表示此探測次數越接近無限；搜尋成功：實際推演。

## 時間複雜度
Big-O 是「最壞情況上界」，不管輸入的資料，執行時間都絕對不會超過這個天花板（上界）。
各時間複雜度的經典範例 (由慢到快排列)：
1. **O(1) 常數時間**：
    1. 陣列索引查詢
    2. 奇偶數判斷：判斷一個數字是不是偶數（只看最後一個位元）。
    3. 堆疊 (Stack) 操作：把資料推入 (Push) 或彈出 (Pop) 堆疊頂端。
    4. 雜湊表 (Hash Table)
2. **O(log n) 對數時間**，利用演算法「每執行一次，就把剩下的資料量砍半」，所以時間成長緩慢。
    1. 二分搜尋法 (Binary Search)：將已經排序過的資料從中間切開，看目標在左半邊還是右半邊，每次都淘汰掉一半的資料。
    2. 二元搜尋樹 (BST)：資料像樹枝一樣往下長，比節點小的往左走，比節點大的往右走，每走一步就過濾掉另一半的資料。
    3. 快速冪演算法：把次方數對半拆，例如算 2 的 8 次方，可以先算 2 的 4 次方再自我相乘，大幅減少相乘次數。
3. **O(n) 線性時間**，不屬於「比較排序」，對資料有很強的限制。
    1. 線性搜尋 (Linear Search)：從第一筆資料開始，一個接一個往下對答案，直到"找到為止"。(重點是「找特定目標」)
    2. 找最大/最小值：拿一個變數當作目前最大值，把所有資料從頭到尾看過一遍，遇到更大的就替換。
    3. 走訪結構：順著資料的排列順序，把裡面的每一個元素都從頭到尾讀取過一次。(重點是「全部處理」)
3. **O(n log n) 線性對數時間**，通常是「高效排序演算法」的極限。
    1. 合併排序 (Merge Sort)：把所有資料一直對半切，直到變成一個個單獨的數字。將兩兩有序的分組，依照大小順序重新組合成更大的有序分組。
    2. 快速排序 (Quick Sort)：隨便挑一個基準點(三數取中法)，比它小的丟左邊，比它大的丟右邊。然後左右兩邊繼續重複一樣的動作。
    3. 堆積排序 (Heap Sort)：先把資料排成一棵「父節點永遠最大」的樹狀結構，然後每次把最大的頂端節點拿出來放到最後面。
4. **O(n^2) 平方時間**，通常出現在雙層迴圈的程式碼中。
    1. 氣泡排序 (Bubble Sort)：兩兩比較並交換位置的簡單排序。
    2. 選擇排序 (Selection Sort)：將資料看成兩堆，一堆已排序，一堆未排序；未排序的資料挑一個"最大"或"最小"，放到已排序的前面或後面 (用交換的方式解決(原地排序))
    3. 插入排序 (Insertion Sort)：將資料看成兩堆，一堆已排序，一堆未排序；從未排序區抓取第一個數，把它跟「已排序區」的數字由後往前比對，只要發現比它大，就往後挪，直到找到正確位置「塞」進去。
    4. 二維矩陣走訪：因為資料有橫排跟直列，必須用兩個迴圈，跑完每一排裡的每一個格子。
5. **O(2^n) 指數時間**
    1. "遞迴"費氏數列：計算第 n 項時，會同時呼叫算 n-1 和 n-2 項，每一項又會再呼叫兩次，像細胞分裂一樣瘋狂展開。遞迴：程式碼自己呼叫自己。
    2. 河內塔問題 (Tower of Hanoi)：遞迴處理的話，要把 n 個盤子移到另一柱，必須先把 n-1 個盤子移開，步驟數會隨盤子數量呈指數翻倍。
    3. 冪集 (Power Set)：找集合的所有子集。每個元素都有「選」或「不選」兩種可能，全部組合起來就是 2 的 n 次方種。(看有哪些成員被選出來，用{}表示，順序不重要) vs 排序(看成員排成的隊伍長什麼樣，用()表示)
6. **O(n!) 階乘時間**
    1. 旅行推銷員問題 (TSP) 暴力破解法：把所有的城市排列組合都列出來算距離，城市越多，排列方式就以階乘暴增。
    2. 全排列 (Permutations)：所有可能的隊伍排列組合，N!。

## 額外空間複雜度
1. **O(1)：常數空間 (Constant Space)**
    1. 找出陣列中的最大值
    2. 判斷一個數字是不是偶數
    3. 雙指標原地交換（例如反轉陣列）。
2. **O(log N)：對數空間 (Logarithmic Space)**
    1. 快速排序（Quick Sort）
    2. 二元搜尋法（Binary Search）的「遞迴」寫法。
3. **O(N)：線性空間 (Linear Space)**
    1. 複製陣列
    2. 合併排序（Merge Sort）
    3. 使用雜湊表（Hash Map / Dictionary）記錄出現過的單字頻率
4. **O(N^2)：平方空間 (Quadratic Space)**
    1. 二維的「相鄰矩陣」（記錄圖形中每個節點到其他節點的距離）
    2. 某些動態規劃（Dynamic Programming）演算法的查表陣列。

## 陣列與線性資料結構

### 陣列
連續記憶體、大小固定的一排格子，用索引 (index) 存取。
**二維陣列**：
A[3][4] (3 列 4 行,索引從 0) 
     行0  行1  行2  行3
列0  A00  A01  A02  A03
列1  A10  A11  A12  A13
列2  A20  A21  A22  A23
純粹排序問題:
以列為主；C類型的語言，列跑完，在跳行
以行為主；
--
A[1..4][1..5]  [下界..上界]表示法，表示列是從 1~4，但行1~5
--
陣列 隨機存取 O(1)、插入/刪除 O(n)、大小固定。

### 動態陣列
本質是陣列，但當原本的空間不足，會從記憶體尋找更大的空間，把原記憶體的內容複製到新記憶體位置，然後原記憶體位置內容刪除。       
```java
// 建立一個空的動態陣列 (專門裝字串)
ArrayList<String> box = new ArrayList<>();
// 無中生有(從後方插入)
box.add("感冒藥"); // O(1)
// 插隊，如果有移動後面的資料，是O(n)
box.add(1, "頭痛藥");     
// 讀取 索引 的值
String firstItem = box.get(0);
// 直接覆寫：找到該位置，直接替換新值。 (O(1))
box.set(2, "益生菌"); 
// 刪除索引 0 的「感冒藥」。後面的藥會自動往前遞補！
box.remove(0);
// 點名，看現在實際裝了幾個藥
int total = box.size();
```

### 鏈結陣列/連結串列/Linked List
1.  插入/刪除 O(1)、走訪/存取 O(n)；與陣列相反
2.  單向 (Singly)：一個 next 指標(尾接 null)，只能往前走。
    雙向 (Doubly)：有 prev + next，可雙向走訪。
    環狀 (Circular)：最後一個節點指回第一個，繞成一圈。

### 堆疊 (stack)
後進先出 LIFO。
1. 本質其實是 interface，但JAVA沒設計好，所以可以寫成以下。
```java
Stack<Integer> st = new Stack<>();
st.push(1);            // 放入 1
int top = st.peek();   // 偷看最上面(不取出)1
int a = st.pop();      // 取出最上面 1
```
2. **經典應用**：
    1. 括號配對檢查，左括號：壓進堆疊；右括號：配掉一個左括號
    2. 函式呼叫的返回位址、瀏覽器「上一頁」、遞迴、回溯 (backtracking)。
    3. 中序轉後序 (運算式)
    4. 運算式求值
        電腦在底層其實會同時開啟兩個 Stack 來分工合作：
        數字堆疊 (Number Stack)： 專門用來放數字。
        符號堆疊 (Operator Stack)： 專門用來放 + - * / 和 ( )。
        電腦的最高指導原則（門禁規則）只有兩條：
        *   規則 A（權重壓制）： 準備進 Stack 的符號，如果權重「小於或等於」Stack 頂端的符號，就必須把頂端符號踢出來，並從數字堆疊抽出兩個數字「先算」，算完的結果再丟回數字堆疊。
        *   規則 B（括號特權）： 左括號 ( 權重最高，可以直接進場。遇到右括號 ) 時，就一路把符號踢出來計算，直到撞見左括號為止。

### 佇列 (Queue)
先進先出 FIFO (First-In, First-Out)，像排隊，先到的先服務。(習慣上是尾端進，前端出)
1. 操作：enqueue(從尾端 rear 入列)、dequeue(從前端 front 出列),O(1)。
2. Queue 是介面 (Interface)，
```java
Queue<String> q = new ArrayDeque<>(); // 動態"環形陣列"，效能好
// Queue<String> q = new LinkedList<>(); // 雙向鏈結串列，記憶體開銷大
// 把元素排到隊伍的最後面。
q.offer(e);
// 把隊伍最前面的元素拿出來並刪除。
q.poll();
// 看隊首
q.peek();
```

**環狀佇列**是為了要解決 Queue + Array ，假溢位(空間浪費)
1. 環狀佇列如何改善 → 用 % size 讓 front/rear 繞回，循環利用空間
2. 如何判斷空與滿 →
    1. 額外用計數器 count — 記錄目前有幾個元素。空:count == 0; 滿:count == size(enqueue 時 count++、dequeue 時 count--)。好處:可以裝滿全部 m 格。
    2. 犧牲一格(最常見)。空:front == rear；滿:(rear + 1) % size == front。代價:m 格的陣列只能裝 m − 1 個元素。

### 雙向佇列（Deque）
前後兩端(First/Last)可以：加入元素、刪除元素、查看元素。
```java
Deque<String> line = new ArrayDeque<>();

// 從前端加入 (特權插隊到最前面)
line.offerFirst("VIP特權客"); 
// 從尾端加入 (類似一般的 Queue 正常排隊)
line.offerLast("正常客A");        

// 看前端
System.out.println("隊伍最前面的是誰: " + line.peekFirst()); // 印出: VIP特權客
// 看尾端
System.out.println("隊伍最後面的是誰: " + line.peekLast());  // 印出: 正常客B

// 拔除前端
String served1 = line.pollFirst();
// 拔除尾端
String cancelled = line.pollLast();
```

## 樹狀結構

*   **歪斜樹 (Skewed)**：每個節點最多只有 1 個子節點
*   **嚴格二元樹 (Strictly Binary Tree)**：每一個非樹葉節點（內部節點）都必須有剛好 0 或 2 個子節點。
*   **完滿二元樹 (Full Binary Tree) & 完美二元樹 (Perfect Binary Tree)定義**：
    這是一棵高度為 k，且擁有剛好 2^k - 1 個節點的二元樹。第 i 層，最多有 2^(i-1) 個節點。也就是說，就是一個塞好塞滿的實心三角形。所有的內部節點都有 2 個小孩，而且所有的樹葉都停在同一層。
*   **完整二元樹(Complete Binary Tree)**：由左至右填滿，不准有人中途插隊，但最後一排可以沒排滿。
    Heap，陣列 (Array)。左小孩的位置：2i，右小孩的位置：2i + 1；父節點 (爸爸) 的位置：Math.floor(i/2)  // 無條件捨去

### 二元樹走訪
每個節點都有左（左小孩）、中（自己）、右（右小孩）。所謂的「前序、中序、後序」，完全是看「中（自己）」排在哪個位置。
*   **BFS (廣度優先搜尋)，遞迴**
    *   前序 Preorder：中 → 左 → 右
    *   中序 Inorder：左 → 中 → 右
    *   後序 Postorder：左 → 右 → 中
    *   只有「前序+中序」或「後序+中序」能唯一決定一棵樹
*   **DFS (深度優先搜尋)，佇列**
    *   層序 Level-order：一層一層由上而下，且由左至右
*   二元樹的陣列表示法，用層序的方式 拆成 陣列。但預設 Array[0] 空著不用，Root 放在 Array[1]

### 二元搜尋樹(BST)
1.  左子樹都比自己小、右子樹都比自己大
2.  平均搜尋 O(log n)、最壞 O(n):當資料按順序插入，BST 退化成歪斜樹(像一條鏈結串列)。
3.  對 BST 做中序走訪 (Inorder),會得到由小到大排序的結果
4.  平衡樹(如 AVL、紅黑樹) 會透過旋轉維持左右高度平衡，避免退化成歪斜樹，保證 O(log n)。
5.  底層是指標
*   **BST 的插入與刪除()**：
    *   插入：從根開始比大小，比目前節點小往左、大往右，一路走到空位就掛上去。
    *   刪除分三種情況：葉節點(沒有子節點)：直接刪掉。只有一個子節點：用那個子節點頂上來取代它。有兩個子節點：中序前驅(左子樹的最大值)、中序後繼(右子樹的最小值)，兩者擇一即可。

### 堆積 (Heap)
講究「上下階級」
1.  完整二元樹
2.  最大堆 (Max-Heap)：每個節點都 ≥ 它的子節點 → 根最大。最小堆 (Min-Heap)：每個節點都 ≤ 它的子節點 → 根最小。
3.  陣列表示
4.  只要知道自己所在的陣列位置 (Index 設為 i)，左小孩一定在 2i，右小孩一定在 2i+1，父節點 Math.floor(i/2)。
5.  用途：優先佇列 (Priority Queue)，因為最大值或最小值，一定在根，抓走後 只要花 O(log n) 的時間調整一下樹狀結構；堆積排序 (Heap Sort,O(n log n))。

### 運算式表示法
1. 把一個 運算式，轉換成前中後序
    *   A × B + C × ( D − E ) = A B × C D E − × + (後序) = + × A B × C - D E
2. 後序用堆疊求值，ex. 6 2 3 + × 8 4 / −
    *   遇到數字就 push；遇到運算子就 pop 兩個出來算，先 pop 的當右運算元、後 pop 的當左運算元，算完把結果 push 回去。
    *   [6,2,3] > [6,2+3] > [6*5] > [30,8,4] > [30,8/4] > [30-2]

### AVL樹
平衡因子：左子樹高度 - 右子樹高度 = {-1, 0, 1}。
1. **插入流程 (中位數法，可以應用在刪除)**：
    1. 照 BST 規則，新節點掛在 null 的位置，一定是葉 (放在對應位置)
    2. 往上退，尋找失衡的爺爺節點
    3. 從爺爺 往下走兩步，鎖定「關鍵三節點」 找出爺爺、爸爸、孫子 (孫子若一樣高，挑選能與爺爸一直線的)
    4. 中位數法(選擇題用)：
        1. 找出排在中間的那個數字（中位數）。
        2. 把這個中位數直接往上提拔，讓它取代原本爺爺的位置，成為這個局部子樹的新根節點。
        ps. 萬一 把中位數往上拉的時候，中位數原本底下可能已經有掛著其他子樹，因為老大搬家，變成孤兒。
        3. 把孤兒的根節點數字0，從根開始跑，拿去跟剛剛重組好的三個關鍵節點比大小，放到對應的位置。
    5. 剩下兩個點，依「小左大右」歸位
2. **往下走兩步，找出形狀。利用形狀，找出對應的旋轉方式**：
    1.  LL 型 (左左失衡)： 節點的左子樹過高，且新節點插在「左子樹的左側」。解法： 對失衡節點作單次右旋 (Single Right Rotation)。
    2.  RR 型 (右右失衡)： 節點的右子樹過高，且新節點插在「右子樹的右側」。解法： 對失衡節點作單次左旋 (Single Left Rotation)。
    3.  LR 型 (左右失衡)： 節點的左子樹過高，但新節點插在「左子樹的右側」。解法： 雙重旋轉。先對左子節點左旋（轉成 LL 型），再對失衡節點右旋。
    4.  RL 型 (右左失衡)： 節點的右子樹過高，但新節點插在「右子樹的左側」。解法： 雙重旋轉。先對右子節點右旋（轉成 RR 型），再對失衡節點左旋。
3. **N(h)** = 「高度是 h 的 AVL 樹,最少要幾個節點」
    *   N(h) = N(h−1) + N(h−2) + 1 (前兩項相加，再 +1)
    *   N(0) = 0、N(1) = 1

### 紅黑樹
黑高：bh(x) = 從 x 往下，到任一 NIL 的路徑上，黑節點的個數
**定義**：
1.  是BST
2.  根是黑
3.  每個葉節點(NIL)是黑
4.  紅節點的兩個小孩都是黑
5.  從任一節點到其下方每一個 NIL,經過的黑節點數目相同
**結論**：
1.  黑高 b ，內部節點數介於 2^b - 1 (完美二元樹，沒有紅節點) ~ 2^2b - 1，要盡可能添加紅節點，黑紅交替
2.  b <= h <= 2b
3.  含 NIL 時，黑節點必定比紅節點多
4.  只算內部節點時，黑比紅多是錯的 ✗ (紅最多可達黑的 2 倍)  ex. 黑紅
**插入規則(中位數版)**：
0.  新節點 Z，父節點P，祖父節點 G 以及叔叔節點 U
1.  將新節點 Z 依照「左小右大」的規則插到樹的最底層，並塗成紅色
2.  P是黑色，結束。P是紅色，要進行修正。
3.  U是紅色，P、U塗黑，G塗紅。上拋檢查： 因為G 變紅了，把 G 視為新的 Z，檢查它和它的父親有沒有再度發生連續紅。U是黑色，G、P、Z排列順序。
4.  G、P、Z，中位數當老大，然後中位數塗黑。剩餘兩個當左子及右子，塗紅。
5.  孤兒歸位（掛回子樹），原本掛在這三個節點底下的所有子樹（包含剛剛在一旁的U），現在變成無家可歸的孤兒。請把它們當作一般的數值，從剛剛重組好的新老大開始，依照「左小右大」的規則重新塞回去。
6.  根節點塗黑(鐵律)
