## 分頁與分段記憶體管理

### 1. 基本觀念
1. 邏輯位址 (Logical Address) / 虛擬位址 (Virtual Address)：程式自己看到的位址，從 0 開始編。程式以為自己獨佔整片連續的記憶體。
2. 實體位址 (Physical Address)：資料真正放在實體記憶體 (RAM) 上的位址。
3. MMU (Memory Management Unit, 記憶體管理單元)：一個硬體，負責在程式執行時，將邏輯位址即時轉換為實體位址。
4. **內部碎裂 (Internal Fragmentation)**：分配給程式的記憶體空間大於其實際需求，導致區塊內部有沒用到的剩餘空間。（通常發生在**固定大小**的切割方式）
5. **外部碎裂 (External Fragmentation)**：記憶體中總剩餘空間足夠，但因為空間不連續（被切得太零碎），導致無法分配給需要大連續空間的程式。（通常發生在**變動大小的**切割方式）

### 2. 分頁系統 (Paging) 空間等大、離散存放
**核心概念**：
1. 分頁是**作業系統/硬體**的觀點。它不管你程式的邏輯，直接把記憶體切成 **固定大小 (Fixed Size)** 的方塊。
```text
🧑‍💻 邏輯記憶體 (程式)                💾 實體記憶體 (RAM)
     (切成 分頁 Page)                   (切成 頁框 Frame)

+-------------------+              +-------------------+
|   Page 0 (4KB)    |  --------->  |   Frame 0 (4KB)   |
+-------------------+              +-------------------+
|   Page 1 (4KB)    |  --------->  |   Frame 1 (4KB)   |
+-------------------+              +-------------------+

* 頁面大小 (Page Size) 必須永遠等於 頁框大小 (Frame Size) 且是 固定大小
```
2. **有 內部碎裂 (Internal Fragmentation)**：配置出去的記憶體空間比實際需要的大，多出來、用不到的部分在內部被浪費掉了。
3. 頁表 (Page Table)：記錄「第幾頁 ➔ 放在第幾個頁框」的對照表，每個程序擁有一份。

4. 延伸考點（多層頁表）：若邏輯空間極大，單層頁表本身會佔用過多記憶體。此時會採用多層頁表 (Multi-level Paging)，將頁表分級，需要時才載入以節省空間。

5. **位址翻譯 (Address Translation)**：
    1. 邏輯位址 = [ 頁號 p | 頁內偏移 d ]
    2. 實體位址 = [ 框號 f | 頁內偏移 d ] （其中偏移 d 直接照抄）。
    3. 原理說明：因為「頁大小 = 頁框大小」，資料搬移前後在格子裡的相對位置（偏移量）完全不會變，這也是偏移量能直接照抄的根本原因。
    4. 範例：假設系統的頁面大小為 4KB。某個程式的頁表已知包含以下對應：頁號 1 ➔ 框號 7，頁號 2 ➔ 框號 5。若 CPU 發出了一個邏輯位址 0x2A3F（十六進位），請計算出對應的實體位址。
        1. **找出頁內偏移 d 的 bits 數（由頁大小決定）**：
            * 頁面大小是 4KB = 2^12 bytes。這代表偏移量 d 佔用 12 bits。
            * 在十六進位中，一個數字代表 4 bits，因此 12 bits 剛好是最後的 3 個十六進位數字。
        2. 邏輯位址 = [ 頁號 p | 頁內偏移 d ]，邏輯位址是 0x2A3F：
            * 後 3 碼 A3F 是頁內偏移 d
            * 剩下的最前面那碼 2 就是頁號 p
        3. 解
            * 頁號 2 ➔ 框號 5
            * 頁大小 = 頁框大小，偏移照抄
            * 0x5A3F
6. **位元 (Bits) 分配與計算公式**：
    1. 偏移 bits (offset)：由「頁大小（或頁框大小）」決定
        1. 若大小為 2^n bytes，則偏移為 n bits。
        2. 頁面大小 (Page Size，單一頁面的容量) 絕對是 2 的次方
    2. 頁號 bits：用來決定邏輯空間裡總共有多少**頁**。由「邏輯位址空間大小（或邏輯位址總位元數）」決定。
    3. 框號 bits：用來決定實體 RAM 裡總共有多少**框**。由「實體記憶體空間大小（實體 RAM 大小）」決定。
    4. 範例：假設一台電腦系統採用 32 位元的邏輯位址空間，安裝了 256MB 的實體記憶體 (RAM)，且分頁系統的頁面大小設定為 8KB。請問：該系統的偏移位元、頁號位元、框號位元分別是多少？
        1. **偏移 bits (offset) —— 由「頁大小」決定**：
            *   8KB = 8 * 1024 bytes = 2^13 bytes。
            *   因為大小是 2^13，所以偏移量需要 13 bits。
        2. **頁號 bits —— 由「邏輯位址空間大小」決定**：
            *   32 - 13 = 19 bits
            *   這也代表該程式最多可以被切成 2^19 個頁
        3. **框號 bits —— 由「實體記憶體空間」決定**：
            *   256MB = 256 * 1024 * 1024 bytes = 2^8 * 2^20 = 2^28 bytes。
            *   這代表實體位址總共需要 28 bits
            *   2^28 / 2^13 = 2^15 bytes。
            *   框號 bits = 實體位址總位元 - 偏移位元(頁框大小位元) = 28 - 13 = 15 bits。
    
7. **TLB (Translation Look-aside Buffer, 轉譯後備緩衝區)**：
    1. 基本概念：一塊極快的小快取，專門存「最近用過的 頁號 ➔ 頁框號」對照。
    2. TLB 命中 (hit)：要找的頁號在 TLB 裡 ➔ 直接拿到頁框號，僅需存取 **1** 次記憶體（直接讀資料）。
    3. TLB 未命中 (miss)：TLB 裡沒有 ➔ 必須先去記憶體讀頁表拿到頁框號，再去讀資料，共需存取 2 次記憶體。
    4. 有效存取時間 (EAT) = 命中率 * 命中所需時間 (讀資料 + 查TLB) + 未命中率 * 未命中所需時間 (讀資料 + 讀頁表 + 查TLB)
    5. 範例：在某分頁系統中，存取一次實體記憶體需要 100ns，搜尋 TLB 需要 10ns。若 TLB 的命中率為 90%，且假設所需資料皆已在 RAM 中（無 Page Fault），請計算該系統的有效存取時間 (EAT)。
        1. **TLB 命中 (Hit) 的時間 —— 僅需 1 次記憶體存取：**查 TLB 找到對應 (10ns) + 拿框號去讀取記憶體資料 (100ns) = 110ns。
        2. **TLB 未命中 (Miss) 的時間 —— 需 2 次記憶體存取：**查 TLB 發現沒有 (10ns) + 去記憶體讀頁表拿框號 (100ns) + 去記憶體讀取資料 (100ns) = 210ns。
        3. 0.9 * 110 + 0.1 * 210 = 120ns

8. **頁表項目 (Page Table Entry)**：
    1. 頁框號 (Frame Number)，告訴硬體這個邏輯頁目前被存放在實體記憶體的哪一個框號裡。
    2. 有效/無效位元 (Valid / Invalid Bit)：
        *   Valid (1)：資料已經在 RAM 裡面，可以安全讀取。
        *   Invalid (0)：資料還在硬碟裡，這時候硬體會馬上發出一個中斷，稱為 "Page Fault (分頁錯誤)"，叫作業系統去硬碟把資料搬進 RAM。
    3. 保護位元 (Protection / Access Bits)，分頁系統的「保護機制」，控制這個頁的存取權限。通常包含 R (唯讀 Read)、W (可寫入 Write)、X (可執行 Execute)。
    4. 髒位元 / 修改位元 (Dirty / Modified Bit)，記錄這個頁自從被載入記憶體後，「有沒有被修改過」。
    5. 參考位元 / 存取位元 (Reference / Accessed Bit)，記錄這個頁「最近有沒有被使用過」（不管是讀取還是寫入）。

### 3. 分段系統 (Segmentation) 依邏輯切塊、大小不一
**核心概念**：
1. 分段是**使用者/設計師**的觀點。依照程式模組（主程式、堆疊等）切割，每一塊**大小不一樣 (Variable Size)**。

```text
🧑‍💻 邏輯記憶體 (程式)                💾 實體記憶體 (RAM)

+-----------------------+          +-----------------------+
|  Segment 0: 主程式段    | -------> |  Segment 0 (主程式)     |
+-----------------------+          +-----------------------+
                                   |  (閒置空間 Free 2KB)   |  <-- 碎裂開始產生
+-----------+                      +-----------+-----------+
| Seg 1: 堆疊| -------------------> | Seg 1 (堆疊)           |
+-----------+                      +-----------+-----------+
                                   |  (閒置空間 Free 4KB)   |  <-- 碎裂開始產生
```
2. 有**外部碎裂 External Fragmentation**：空閒的記憶體總容量足夠，但因為被切成零碎、不連續的小塊，導致無法滿足一個較大的連續記憶體需求。 (圖解當中的 Free空間，不規則大小、零碎)
3. **段表 (Segment Table)**：
    1. 基底 (Base)：該段在實體記憶體中的起始位址。
    2. 界限 (Limit)：該段的長度（有多大）。

4. **位址翻譯與保護機制**：
    1. 邏輯位址 = [ 段號 s | 段內偏移 d ]
    2. 檢查步驟：拿段號，查段表，拿到該段的 base 與 limit。
    3. 安全性檢查：檢查 d < limit（超重要考點：是小於而非小於等於，若 d = limit 即為超界）。(因為從0開始)
    4. 若檢查未通過，硬體會發出「段錯誤 (Segmentation Fault / Trap)」中斷程式。
    5. 若通過，則 實體位址 = base + d（相加得出，不可照抄）。 
    6. 範例：假設某作業系統採用分段記憶體管理機制，目前有一支程式正在執行，其段表資訊如下：<br>
        | 段號 (s) | 基礎位址 (Base) | 長度限制 (Limit) |
        | :---: | :---: | :---: |
        | 0 | 219 | 600 |
        | 1 | 2300 | 14 |
        | 2 | 90 | 100 |
        | 3 | 1327 | 580 |
        | 4 | 1952 | 96 |

        *   請根據上述段表，將 CPU 發出的**邏輯位址**轉換為**實體位址**。若無法轉換，請說明原因及系統的處置方式。
            1. 邏輯位址：`[ 0 | 430 ]`
                * **拆解位址**：段號 s = 0，偏移量 d = 430。
                * **查表**：段號 0 的 base = 219，limit = 600。
                * **安全性檢查**：d (430) < limit (600)，**檢查通過**。
                * **計算實體位址**：base + d = 219 + 430 = **649**。
                * **✅ 最終答案：實體位址為 649。**
            2. 邏輯位址：`[ 1 | 10 ]`
                * **拆解位址**：段號 s = 1，偏移量 d = 10。
                * **查表**：段號 1 的 base = 2300，limit = 14。
                * **安全性檢查**：d (10) < limit (14)，**檢查通過**。
                * **計算實體位址**：base + d = 2300 + 10 = **2310**。
                * **✅ 最終答案：實體位址為 2310。**
            3. 邏輯位址：`[ 2 | 100 ]`
                * **拆解位址**：段號 s = 2，偏移量 d = 100。
                * **查表**：段號 2 的 base = 90，limit = 100。
                * **安全性檢查（⚠️ 超界陷阱）**：d (100) 與 limit (100) 相等。因為位址偏移是從 0 開始計算，所以 d 必須「嚴格小於」limit。
                * **計算結果**：檢查未通過，100 並未小於 100。
                * **❌ 最終答案：發生超界錯誤 (Trap)，硬體會發出 Segmentation Fault (段錯誤) 中斷程式。**
            4. 邏輯位址：`[ 3 | 585 ]`
                * **拆解位址**：段號 s = 3，偏移量 d = 585。
                * **查表**：段號 3 的 base = 1327，limit = 580。
                * **安全性檢查**：d (585) > limit (580)。
                * **計算結果**：檢查未通過，偏移量明顯大於該段的長度限制。
                * **❌ 最終答案：發生超界錯誤 (Trap)，硬體會發出 Segmentation Fault (段錯誤) 中斷程式。**


5. 緊縮 (Compaction)
    1. **目的**：為了解決分段系統產生的外部碎裂。
    2. **做法**：將目前正在使用、散落在記憶體各處的「段」全部搬移到記憶體的一邊，使它們緊緊靠在一起，將原本零碎的小空洞合併成一整塊連續的大空間。
    3. **前提**：程式在執行期間必須是可動態重定位的 (Dynamic Relocatable)。
    4. **缺點**：搬移大量記憶體資料的系統成本與時間極高。

### 4. 分頁 vs 分段 核心對比
1.  切割單位：
    *   分頁為固定大小（不管程式邏輯）；
    *   分段為邏輯單位（大小不一）
2.  碎裂類型：
    *   分頁有內部碎裂（無外部碎裂）；
    *   分段有外部碎裂（無內部碎裂）
3. 重定位法：
    *   分頁為「框號 * 框大小 + 偏移（偏移照抄）」；
    *   分段為「基底 (Base) + 偏移（相加）」
4. 對程式設計師的可見性：
    *   分頁為透明 (Transparent)（由硬體處理）；
    *   分段為可見 (Visible)（依程式結構規劃）
5. 對照表記錄欄位：
    *   分頁僅記錄「框號」；
    *   分段記錄「Base」與「Limit」
6. 解決碎裂方案：
    *   分頁無外部碎裂，不需處理；
    *   分段可透過緊縮 (Compaction) 解決
7. 觀念口訣：分段外、分頁內

### 6. 段頁式記憶體管理 (Paged Segmentation)
**核心概念**：外層採用「分段」符合程式邏輯，接著把每一個段再採用「分頁」進行實體配置。是實務上最常用的折衷方案。
```text
 (1) 先依邏輯分段                 (2) 再將每個段切成「等分」的分頁
+-----------------------+      +--------+--------+--------+      +-----------+
| Segment 0: 主程式段    | ---> | Page 0 | Page 1 | Page 2 | ---> | 塞入 Frame |
| (長度: 10KB)          |      | (4KB)  | (4KB)  | (2KB)⚠️|      +-----------+
+-----------------------+      +--------+--------+--------+       

1. 把邏輯切成很多段，每一段不同大小。
2. 每一個段內部有很多同等大小的頁。
3. 把每一個頁分別塞入FRAME，塞入的FRAME是頁，而不是段。

* 會出現一個段，但內部的頁塞入不連續的FRAME的情形
* 結合分段的「保護與共享」和分頁的「無外部碎裂」優點
```

2. 邏輯位址 = [ 段號 s | 頁號 p | 頁內偏移 d ]
3. **優點**：
    1. 保留了分段的邏輯共享與保護機制。
    2. 徹底解決了外部碎裂問題（因為底層實體配置依然是等大的分頁，不需連續擺放）。
4. **缺點**：
    1. 記憶體存取延遲大幅增加（查表次數變多）」以及**硬體設計複雜度變高**，所以極度依賴 TLB。
    2. 位址變成三維 `(段號, 頁號, 偏移量)`。



5. **位址翻譯步驟**：
    1. 用段號 s 查「段表」，找到該段專屬的「頁表」起始位址。
       *    段頁式的段表：[ 頁表指標 (Page Table Base) | 頁表長度/段的界限 (Page Table Length) ]
    2. 用頁號 p 查該「頁表」，換成實體「框號」。
    3. 實體位址 = 框號 * 框大小 + 偏移 d。
    4. **計算範例**：
       * **系統環境**：
         假設系統的頁框大小 (Frame Size) 為 1000 Bytes。
         **【段表 (Segment Table)】**
         | 段號 (s) | 頁表指標 (Page Table Base) | 頁表長度 / 段界限 (Page Table Length) |
         | :---: | :---: | :---: |
         | 0 | 指向 **頁表 A** | 3 (代表此段有頁號 0, 1, 2) |
         | 1 | 指向 **頁表 B** | 2 (代表此段有頁號 0, 1) |

         **【頁表 (Page Table)】**
         *頁表 A (專屬段號 0 使用)*
         | 頁號 (p) | 實體框號 (f) |
         | :---: | :---: |
         | 0 | 5 |
         | 1 | 12 |
         | 2 | 8 |

         *頁表 B (專屬段號 1 使用)*
         | 頁號 (p) | 實體框號 (f) |
         | :---: | :---: |
         | 0 | 20 |
         | 1 | 7 |

       * **題目一：邏輯位址 `[ 0 | 1 | 450 ]`**
         1. **查段表與檢查界限**：段號 s = 0。查段表得知找【頁表 A】，頁表長度為 3。安全檢查：頁號 p (1) < 頁表長度 (3)，**檢查通過**。
         2. **查頁表**：在【頁表 A】中尋找頁號 1，得到實體框號 f = 12。
         3. **計算實體位址**：12 × 1000 + 450 = **12450**。

       * **題目二：邏輯位址 `[ 1 | 2 | 150 ]`**
         1. **查段表與檢查界限**：段號 s = 1。查段表得知找【頁表 B】，頁表長度為 2。安全檢查：頁號 p (2) **沒有小於** 頁表長度 (2)，發生**超界**！
         2. **查頁表**：第一步安全檢查已失敗，硬體直接攔截，**不會**再去查頁表。
         3. **計算實體位址**：無法計算。發生超界錯誤 (Trap)，硬體會發出 Segmentation Fault。

### 7、 Thrashing (震盪 / 輾轉現象)
1. **定義**：系統花費在「硬碟與記憶體之間搬移頁面 (Page in/out)」的時間，遠大於「CPU 實際執行程式」的時間。
2. **原因**：實體記憶體總容量 < 所有執行中程式的基本需求總和。
3. ⚠️ 選擇題最大陷阱：CPU 誤判連鎖反應（必考因果順序）
    1. **起因**：程式太多，Frame 不夠用，開始頻繁發生 Page Fault。
    2. **現象**：CPU 必須一直等待 I/O 搬資料，導致 **CPU 使用率急遽下降**。（*陷阱：很多考生會誤選 CPU 使用率上升*）
    3. **OS 誤判**：作業系統（CPU 排班器）看到 CPU 很閒，以為系統負載太低。
    4. **致命錯誤**：OS 決定**提高「多元程式等級 (Degree of Multiprogramming)」**，載入更多新程式進來跑。
    5. **結果**：每個程式分到的 Frame 更少，Page Fault 更嚴重，系統徹底癱瘓。
4. 解除 Thrashing 的根本方法
    1. **降低**多元程式等級（暫停一些程式）。
    2. **增加**實體記憶體 (RAM) 容量。
5. 預防 Thrashing 的兩大演算法比較(注重關鍵字)：
| 比較項目 | 1. 工作集模型 (Working Set Model) | 2. 分頁錯誤頻率 (PFF) |
| :--- | :--- | :--- |
| **判斷依據** | 依據程式**過去存取頁面的歷史紀錄** | 依據程式**發生 Page Fault 的次數頻率** |
| **理論基礎** | 基於**局部性原理 (Locality)** | 基於**直接監控錯誤率 (Fault Rate)** |
| **運作方式** | 算出工作集大小，只在 RAM 有足夠空位能裝下「整個工作集」時，才讓程式跑。 | 頻率 > 上限：多配給它 Frame<br>頻率 < 下限：沒收它的 Frame |
| **系統負擔 (Overhead)** | **極高**（隨時都要記錄用了哪一頁） | **較低**（只有發生錯誤時才計算） |



6. 在考卷上看到左邊的敘述，請毫不猶豫尋找右邊的答案：
* 看到「頻繁的 Page in / Page out」選 **Thrashing**
* 看到「Thrashing 時 CPU 的狀態」選 **CPU 使用率下降**
* 看到「Thrashing 時 OS 會怎麼做」選 **提高多元程式等級 (導致情況更糟)**
* 看到「Locality (局部性原理)」選 **Working Set Model (工作集模型)**
* 看到「Upper bound / Lower bound」選 **PFF (分頁錯誤頻率)**


7. **⚔️ 實戰模擬測驗 (附詳解)**<br>

    **Q1. 當系統發生 Thrashing（顛簸）時，下列哪一種現象最正確？**
    > (A) CPU 使用率大幅上升 <br>
    > (B) CPU 使用率大幅下降 <br>
    > (C) I/O 設備處於閒置狀態 <br>
    > (D) 作業系統會自動降低多元程式等級 <br>

    > **解答：(B)** <br>
    > **解析：** Thrashing 代表系統一直在硬碟跟記憶體間搬資料，CPU 只能發呆等資料，所以使用率下降。
    > (C) 錯，I/O 會非常忙碌。(D) 錯，早期 OS 會誤判而「提高」多元程式等級。

    **Q2. 下列哪一種記憶體管理策略，是藉由觀察程式在一段時間內所參考到的頁面集合，來決定分配多少頁框？**
    > (A) 最佳置換演算法 (Optimal Replacement) <br>
    > (B) 分頁錯誤頻率 (Page Fault Frequency) <br>
    > (C) 工作集模型 (Working Set Model) <br>
    > (D) 需求分頁 (Demand Paging) <br>

    > **解答：(C)** <br>
    > **解析：** 看到關鍵字「觀察一段時間內參考到的頁面集合」，秒選 Working Set Model。如果是觀察「錯誤頻率」，才是 (B) PFF。

    **Q3. 若一個行程 (Process) 的分頁錯誤頻率 (PFF) 超過系統設定的上限 (Upper bound)，作業系統應該採取何種行動？**
    > (A) 終止該行程 <br>
    > (B) 減少該行程的頁框數 <br>
    > (C) 增加該行程的頁框數 <br>
    > (D) 將該行程 Swap out 到硬碟 <br>

    > **解答：(C)** <br>
    > **解析：** 頻率太高代表它分到的記憶體不夠用（很渴），所以 OS 應該要「多給它」頁框 (Frame)。
